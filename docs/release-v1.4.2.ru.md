# v1.4.2 — памятка оператора

[English](release-v1.4.2.md) · [Список изменений](../CHANGELOG.md)

## Rebuild и L2TP

### Второй выход через бридж без переустановки L2TP

Исправление для второго выхода рассчитано на штатную пустую конфигурацию Xray, которую Rebuild записывает как заглушку. Это относится и к новым установкам L2TP, и к релеям, на которых L2TP уже установлен в v1.4.1. Используйте обычный предпросмотр Rebuild и Apply («Деплой»); удалять и заново устанавливать L2TP для этого не нужно. Файл заглушки должен совпадать побайтно и иметь ожидаемые владельца и права доступа; юнит `xray-bridge.service` должен отсутствовать. Если панель не может подтвердить, что это штатная заглушка, остановитесь. Не редактируйте, не удаляйте и не заменяйте неизвестную конфигурацию ради прохождения проверки.

### Перед новой установкой L2TP

Сначала примените связь от релея к бриджу в Rebuild. Для Install нужны **оба** подтверждения: запись о применённой связи и совпадение файла профиля MAIN работающего Xray на релее с отпечатком, записанным при Apply. Предварительная проверка выполняется только на чтение, до резервирования установки и любых действий APT. У старой, уже применённой связи нужного подтверждения может не быть. В таком случае проверьте предпросмотр и выполните обычный Apply, а затем запускайте Install. Сохранить связь как черновик недостаточно.

Индикатор Install показывает реальные этапы: предварительная проверка, резервирование, подготовка пакетов при необходимости, подготовка конфигурации, установка, перезапуск служб и проверка результата. Если APT сообщает о распаковке или настройке пакетов, панель учитывает эти этапы. Процент не отсчитывает время, не предсказывает завершение и не подтверждает успех установки.

### Если результат действия в панели не подтверждён

Панель сообщает о подтверждённом результате и обновляет данные запросами на чтение. Если исход неизвестен, панель проверяет его около пяти минут, не повторяя операцию. Если подтвердить исход не удалось, связанные кнопки остаются заблокированными. **Не повторяйте действие и не снимайте блокировку.** Ограничьтесь проверками на чтение и используйте действие восстановления, если его предложит панель.

### Проверка релея перед допуском к L2TP

Скопируйте команду проверки из диалога допуска и выполните её в консоли провайдера, а не по SSH через панель. Сверьте **фактический тип публичного ключа SSH-сервера** и **SHA-256 в шестнадцатеричном виде от декодированных байтов ключа** со строкой того же типа в выводе консоли. Подтверждайте ключ только при совпадении обоих значений. На следующем шаге перед подтверждением допуска сравните идентификатор машины в панели с `/etc/machine-id` из той же консоли. Если данные различаются или их нельзя проверить, не выдавайте допуск. Для проверки нужны только публичные ключи и идентификатор машины; не вставляйте и не передавайте закрытые ключи, пароли, PSK или токены. Допуск не запускает Install.

## API и MCP

- Настройка Xray через `POST /api/nodes/:id/setup` и инструмент MCP `manage_node` с `action: setup` выбирает тот же сценарий по роли ноды, что и панель. Для остальных ролей используется настройка с `cc-agent`. Бридж настраивается только как выход (exit-only): установка Xray не запускает и не перезапускает его службу и не устанавливает агент. Конфигурация бриджа применяется отдельно при деплое каскада.
- Лимит JSON-запроса MCP не изменился: **100 КиБ (102 400 байт)**. Если JSON-запрос к `POST /api/mcp` превышает лимит, сервер отвечает HTTP `413` с локализованной ошибкой JSON-RPC и просьбой уменьшить размер запроса. Уменьшите тело запроса, а не отправляйте его повторно в прежнем виде.

Версия `cc-agent` остаётся **1.5.1**. Обновление панели не обновляет агентов на нодах.
