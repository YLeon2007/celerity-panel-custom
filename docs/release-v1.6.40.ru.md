# C³ CELERITY 1.6.40 — установка L2TP на релей

## Что изменилось

- На странице L2TP допуск и состояние релея обновляются без ручной перезагрузки. Установка показывает процент, название этапа и причину подтверждённого отказа.
- Если установщик обнаружил чужие настройки протокола L2TP, он не изменяет их при первом запросе. Панель показывает список обнаруженных настроек и ждёт решения оператора. Отмена не посылает запрос на релей.
- На релее с актуальным допуском из базы разрешение на удаление одноразовое, действует 10 минут и привязано к релею, поколению допуска, сеансу оператора и отпечатку настроек. Если настройки изменились, оператор видит новый список. Если хотя бы один путь нельзя обработать безопасно, удаление кнопкой недоступно.
- Активный VPN, занятые порты, PPP-сессии или неизвестное состояние хоста не дают удалить настройки. Перед изменениями сохраняются исходные байты и права. Для исправления прав известных юнитов Xray действует отдельная галочка; сам этап исправления прав не перезапускает Xray.
- При подтверждённом восстановлении панель сообщает, что чужие настройки восстановлены. Если исход неизвестен, не запускайте установку заново: сохранённое состояние нужно сначала сверить. Аудит содержит оператора, время, релей, список известных ключей и путей и исход; содержимое файлов и подтверждение в открытом виде не записываются.

## Что остаётся на релее после подтверждённого Remove

- Если установка включала согласованную очистку чужих настроек, Remove заменяет `manifest.json` в `/var/lib/celerity-rebuild-l2tp-direct/<backupId>/` записью только с полями `phase: "removed"` и `backupId`. Снимков исходных файлов в этом манифесте больше нет. При установке без такой очистки Remove сохраняет исходный манифест установки.
- В обоих случаях каталог операции и `remove-attempt.json` с отпечатком состояния перед удалением остаются. Каталог с тем же `backupId` защищает от повторной доставки старого Install; Remove не удаляет эти записи автоматически. Не удаляйте их вручную только потому, что панель подтвердила Remove.
- Remove не восстанавливает чужие настройки, удалённые при установке. Восстановление после неудачной установки (rollback/recover) — отдельная операция; оставшиеся записи Remove не дают способа вернуть удалённую конфигурацию через панель.

## Статус приёмки

Это кандидат для TEST, не финальная выкладка. На `rebuild-r` оператор проверил Install и Remove со специальной TEST-подменой проверки PPP для `systemd-nspawn`. Живой повтор сбоя на новом кандидате и проверка без подмены на VM остаются отдельными этапами.

Новый Install записывает в VAULT, какие команды служб завершились. После подтверждённого сбоя сначала откатываются файлы и службы установки, затем восстанавливаются исходные байты и права из VAULT. Если команда могла остаться в работе, исход остаётся неизвестным. Старый `applying` без `swanStart` и без новых записей не доказывает завершение команд; отсутствующий `before.boot` не заменяется текущим идентификатором загрузки. Такой манифест новая версия автоматически не принимает.
