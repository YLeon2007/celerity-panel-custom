# Any-order: ограниченная миграция classic и откат

## 1. Статус, исходники и предел разрешения

Это инструкция подготовки **этапа 7 утверждённого ТЗ**, а не выполненная миграция или разрешение на её запуск. Все исторические ссылки на исходники ниже (кроме отдельно помеченной errata Wave 12) относятся только к immutable commit **`1fa320fefbecd077d070dd076bdedfedac67f758`**. Ссылки имеют вид `путь:Lначало-Lконец`; рядом указан проверенный символ. Исторический serving commit из ТЗ не используется для вывода о текущем коде. Изменения отдельного владельца TEST inventory после этой точки требуют своей проверки и не считаются уже принятыми здесь.

Разрешённая будущая стендовая работа — адаптация существующего TEST authority path к вновь выделенному изолированному inventory. Пользователь отдельно разрешил при необходимости проверять **CLASSIC `портал → бридж` Финляндии**. Это **не** разрешение на native production adoption, native rollout или обновление всей панели. Точный Finland link/endpoints/shared profiles устанавливаются отдельным актуальным inventory до любого live write; этот документ их не угадывает. Неиспользуемый relay cascade не делает остальные classic-связи свободными. **Латвия / link `6aea199fd4a01ba2c1b48194` и остальные рабочие classic-связи сохраняются.** Старый recovery/DAC не возобновляется; журналы, locks и reservations не обнуляются.

Здесь не запускались приложение, тесты, DB, SSH/MCP, deploy, capture, enrollment или службы. Реальная репетиция backup → migration → rollback, оба класса клиентского трафика и совместимость фоновых writers остаются **pending**. Приёмка Finland CLASSIC, если она состоится, не закрывает эти native-критерии.

## 3. Точная граница legacy import/conversion

`src/services/topologyConfigTransfer.js:L31-L81` — `legacyAppliedTopology`; `src/modules/relay-l2tp/repositories/topologyOperationRepository.js:L141-L176` — `durableSelectedTopology`:

- Один связный inventory `{nodes, links, groups}`: **1–32** узла, **1–64** связи, JSON до **4 MiB**, каждый `profileConfig` до **1 MiB**. Узлы — `type=xray`, `active=true`, с уникальными ID и существующими endpoint descriptors; связи ссылаются на эти узлы, имеют допустимые порт и mode.
- Для legacy import все связи **`reverse`**, `active=true`, с сохранённым lowercase UUID `tunnelUuid`; `status` либо отсутствует, либо `online/deployed` и удаляется из принятого applied inventory. `pending`, `staged`, inactive и наличие `lifecycle` в импортируемом дескрипторе отвергаются. Их строки desired DB не удаляют и не активируют: они просто не являются observed applied baseline.
- Portal: нет входящих, ровно один выход. Relay: ровно один входящий, выходы определяются распознанным classic-generator layout. Bridge: один или несколько входящих, нет выходов. Поддержка любого нового Any-order графа не означает, что любой старый граф представим импортом.
- В `groups` требуется **`[]`**. Это ограничение **импортируемого компонента**, не требование удалять посторонние группы из панели.

| Старый профиль/состояние | Что поддержано и что не обещается |
|---|---|
| Portal MAIN | `xray-main`: `/usr/local/etc/xray/config.json`, `/etc/systemd/system/xray.service`, service `xray`. Проверяются generated client listener/transport/key metadata без сравнения mutable user catalog; фактические runtime clients остаются в точных profile bytes. |
| Relay / Bridge | `xray-bridge`: `/usr/local/etc/xray-bridge/config.json`, `/etc/systemd/system/xray-bridge.service`, service `xray-bridge`. Relay — actual classic relay layout; bridge — combined layout, либо старый single-bridge layout при одном входящем. Общий bridge требует всех peer artifacts в inventory. |
| Security | Tunnel и node Xray security — только `none`/`reality`; extra inbounds — та же допустимая пара (у отсутствующего security используется кодовый default `reality`). Сохранение REALITY keys и client metadata проверяется по descriptors/bytes, не их перегенерацией. Остальные transport/options допустимы только если точное сопоставление с реальным classic generator успешно; универсальная совместимость не заявляется. |
| **Не поддержано: forward** | Старые forward listeners могут жить в MAIN не-портала, тогда как этот import выбирает профиль по роли. Отказ **`CONFIG_LEGACY_IMPORT_LAYOUT_UNSUPPORTED`**, не автоматическая перестановка служб/ролей. Новый forward lifecycle и browser-проверка не закрывают legacy forward migration. |
| **Не поддержано: TLS** | Tunnel/node/extra-inbound TLS отвергается: генерация может читать panel certificate files. Это не разрешение временно снять TLS, заменить transport или ключи. |
| **Не поддержано: group migration** | Любой непустой `groups`, включая disabled/empty-path policies, не импортируется этим API. Старый установленный L2TP/group path требует отдельной owner/path authority; копирование desired group в applied запрещено. Native installed-group lifecycle после корректной публикации — другой контракт. Наличие несвязанной группы вне области не повод мигрировать её. |
| Пустой новый профиль | `adopt` без legacy descriptors возможен как ownership transfer; selected reader без settled history принимает только предусмотренные digests пустого `{}`-профиля. Произвольный непустой конфиг без legacy import не становится рабочим baseline. |
| Файлы/службы | Transfer v1 требует существующие config/unit, active state `active/inactive`, enabled state `enabled/disabled/masked`. Hash receipt не поддерживает угадывание отсутствующих файлов, alternative paths, drop-ins или неизвестных unit states. Такие layouts не входят в эту инструкцию. |

Основания матрицы: `src/services/topologyConfigTransfer.js:L10-L24` — `PROFILES`, `snapshot`; `src/services/topologyConfigTransfer.js:L87-L160` — `legacyProfileArtifacts`, `verifyLegacyAppliedProfile`; `src/modules/relay-l2tp/repositories/topologyDeploymentRepository.js:L162-L200` — `readSelected`. Распознавание сравнивает owned reverse entries, listeners, outbounds, порядок owned routing rules и balancers; лишний старый peer нельзя объявить «чужим фрагментом». Несвязанные clients/rules/policy допустимы только вне распознанной owned-области.

Import сам **не пишет node config**, не создаёт фиктивной successful operation и не доказывает tunnel/client readiness. До первой операции все владельцы компонента должны иметь одинаковый private `legacyAppliedTopology`; частичная передача не даёт applied component (`src/modules/relay-l2tp/repositories/topologyDeploymentRepository.js:L250-L271` — `readSelected`).

Conversion — отдельная candidate generation: `src/modules/relay-l2tp/services/topologyOperationPlanMaterializer.js:L339-L368` — `materialize`; `src/modules/relay-l2tp/services/frozenTopologyDeploymentPlanComposer.js:L1865-L1899`, `src/modules/relay-l2tp/services/frozenTopologyDeploymentPlanComposer.js:L1901-L1950`, `src/modules/relay-l2tp/services/frozenTopologyDeploymentPlanComposer.js:L1954-L2035` — `matchedClassicConfigs`, `transitionLinkRefs`, `composeDescriptorTransition`. Удаляются только совпавшие classic artifacts, сохраняются исходный domain suffix, surviving link identities и посторонние profile fragments. Stored UUID используется вместо deterministic fallback (`src/modules/relay-l2tp/services/frozenTopologyDeploymentPlanComposer.js:L963-L975` — `projectCascadeLink`). После settlement текущие bytes берутся из проверенного committed candidate/terminal relationships, **не из старого adoption snapshot** (`src/modules/relay-l2tp/repositories/topologyDeploymentRepository.js:L202-L248`, `src/modules/relay-l2tp/repositories/topologyDeploymentRepository.js:L268-L271` — `readSelected`).

## 4. Backup: минимальный согласованный набор выбранной области

Это перечень необходимых данных, **не новая backup-система**. Хранить приватные bytes и DB dump с ограниченными правами (`umask 077`, файлы только владельцу); секреты и полные конфиги не помещать в отчёт. Публичный evidence содержит IDs и fingerprints. Сохранённые `.env`/encryption key — отдельно защищённый материал, не приложение к публичному архиву. Не запускать офлайн-копию с live credentials.

1. **Приложение/запуск:** точный прежний commit/image/assets и lockfile, runtime версии, команда запуска/unit/env и режимы classic/native, migrations/schema/index versions. Не копировать старый backend поверх новой DB «для проверки». Конфигурация шифрования должна позволять прочитать сохранённые encrypted fields.
2. **Область:** node IDs, роли и физическая идентичность (machine ID, SSH host-key digest), endpoint/port/username, оба профиля и shared service/listener dependencies, link IDs и порядок политик. Для shared profile inventory включает всех работающих соседей, даже если выбран один link. `readSelected` строит union старых и новых ресурсов и отказывает физическим alias (`src/modules/relay-l2tp/repositories/topologyDeploymentRepository.js:L101-L184`). Недоступный независимый узел не добавляют без общей изменяемой зависимости.
3. **Desired DB:** полные исходные HyNode/CascadeLink, включая private credentials/REALITY/transport/geo/priority, active/status/lifecycle; user UUID/назначения/группы/подписки. Сохранить pending/inactive отдельно как намерение, не как applied. Private поля нельзя терять из-за обычной API/schema projection.
4. **Владельцы/операции:** `TopologyConfigOwner` целиком, включая `executionContext`, identity, owner/generation, `originalSnapshot`, adoption/handback receipts, **`legacyAppliedTopology` (`select:false`)**, `lastSettled*`, binding nonce. Связанные topology operations с frozen plans/candidates, intents v1/v2/payload/idempotency, queue state, topology revision/deployedRevision/counters, locks, admissions/reservations, execution enrollments/bindings/terminal receipts и node-side journal/head/backup identifiers сохраняются согласованно, а не выборочным удалением «мешающих» записей. Источник owner fields: `src/models/topologyConfigOwnerModel.js:L25-L51` — `schema`; binding enrollment fields/indexes: `src/modules/relay-l2tp/repositories/topologyExecutionBindingStore.js:L12-L46`, `src/modules/relay-l2tp/repositories/topologyExecutionBindingStore.js:L103-L118` — `ENROLLMENT_KEYS`, `#indexes`.
5. **Node-side:** точные исходные config/unit **bytes**, hashes, файл owner/mode, active/enabled states; используемые drop-ins/agent config, user runtime inventory и существующие backup/journal artifacts выбранной области. Обнаруженный неучтённый drop-in/layout — stop, не попытка расширить v1. `originalSnapshot` хранит только hashes и service states (`src/services/topologyConfigTransfer.js:L15-L24` — `snapshot`); он **не backup bytes** и не restore implementation.
6. **Если область содержит L2TP:** полные `RelayL2tpState` (PSK encrypted/hint/secretRevision, addresses/pools/DNS/MTU/MRU, tproxy/fwmark/table, routeGroup/activePathKey/appliedTopologyRevision, fingerprints/backup/operation IDs и desired/status), `L2tpUser` (IDs/login/relay/IP/enabled, encrypted password, desired/applied revisions и sync operation/status), `CascadeRouteGroup` (ID/mode/strategy, ordered paths/keys/link IDs/priority/enabled) и peer relay references. Не переустанавливать L2TP ради каскада. Источники: `src/modules/relay-l2tp/models/relayL2tpStateModel.js:L17-L88` — `relayL2tpStateSchema`; `src/modules/relay-l2tp/models/l2tpUserModel.js:L13-L58` — `l2tpUserSchema`; `src/modules/relay-l2tp/models/cascadeRouteGroupModel.js:L5-L54` — `routePathSchema`, `cascadeRouteGroupSchema`. Node-side PPP/IPsec/L2TP files, network rules и реальные sessions — отдельный readback, не замена DB credentials.

Штатный `src/services/backupService.js:L76-L96` — `createBackup` — делает `mongodump` и tar DB; в этом вызове нет node/app snapshot или `--oplog`. Его `success` не доказывает согласованный migration checkpoint. Для репетиции нужна доказанная согласованность в остановленной для записей выбранной области и проверенное восстановление копии. Массовый restore production DB с потерей независимых последующих изменений не является scoped rollback.

## 5. Последовательность передачи — только существующие механизмы

Обозначения состояний: **C** — classic; **A** — adopted/imported, ещё без native dispatch; **N** — native операция действительно выполнялась; **H** — original profile восстановлен и handback подтверждён. Это обозначения инструкции, не новые DB enum.

### C → A: допустимый внутренний контракт, operational integration ещё требуется

1. На выделенном стенде зафиксировать current read-only inventory и совместимость из §3, backups из §4, исходную клиентскую работоспособность. Отделить старые unfinished/uncertain операции; они требуют сверки прежнего результата, не удаления истории. Не менять роли, IDs, transport или keys для прохождения import.
2. Внешний authority должен **удерживать** исключение старого backend/process tree и будущего dispatch, drain всех writers выбранных физических профилей/служб и независимый node readback через весь transfer + majority confirmation. Один DB lock/flag или остановленный новый worker этого не доказывает. При неизвестном результате hold не снимается по timeout (`src/services/topologyConfigTransfer.js:L232-L258`, `src/services/topologyConfigTransfer.js:L264-L295` — `#transfer`). Для production такого default adapter нет (§2).
3. Проверить существующий non-sparse/non-partial unique `(node, profile)` index. Вызов **`initializeClassic({node, profile, nodeIdentity})`** только вставляет classic inventory и подтверждает его primary/majority; не изменяет существующий owner и не даёт execution authority (`src/services/topologyConfigTransfer.js:L183-L207` — `#requireUniqueIndex`, `initializeClassic`).
4. Для каждого профиля передать **`adopt({node, profile, generation, proofRef, legacyTopology})`**, где generation — именно возвращённая classic generation, а legacyTopology — один и тот же точный observed component с raw profile bytes. Проверка raw SHA и точных classic artifacts предшествует CAS. Успешный ответ содержит новую generation; сохранить receipt и primary/majority результат. Нельзя продолжать с guessed generation после потерянного ответа (`src/services/topologyConfigTransfer.js:L152-L160`, `src/services/topologyConfigTransfer.js:L212-L295` — `verifyLegacyAppliedProfile`, `#transfer`).
5. Проверить все per-profile owner/import записи и `readSelected`; incomplete component должен отказать. Сохранить прежние pending/inactive desired rows неизменными. На этой стадии нет операции, активации или client acceptance.

### A → N: отдельное явное применение

6. Только при реальной authority выполнить **`preEnroll({nodeId,targetProfile,endpoint,nodeIdentity,ownerGeneration,predecessorGeneration,bootId})`**. `predecessorGeneration='none'` допустим лишь с реальным empty-head/provisioning evidence; не объявлять существующий журнал пустым. API/проверки — `src/modules/relay-l2tp/repositories/topologyExecutionBindingStore.js:L39-L46`, `src/modules/relay-l2tp/repositories/topologyExecutionBindingStore.js:L200-L257`, `src/modules/relay-l2tp/repositories/topologyExecutionBindingStore.js:L291-L317` — `validEnrollment`, `emptyHead`, `#scope`, `preEnroll`. Сквозного CLI «импорт legacy + enroll» здесь нет.
7. Использовать обычное явное selected apply/Auto намерение, его точные job/operation ID и existing worker, а не общий Sync. Проверить generated before/after union, owned fragments, unrelated neighbors, credentials, listener/readback/service, terminal settlement и actual clients. Conversion candidate сам не равен dispatch/settlement. После restart отдельно восстановить и проверить runtime users: `src/modules/relay-l2tp/workers/topologyOperationWorker.js:L988-L1000` — `restoreUsersAfterRollback` прямо различает config restoration и clients.
8. При любой неизвестности сохранить owner/bindings/operations/locks и исключение конфликтующих writers для сверки. Выключить native-флаг, удалить стрелку/owner или запустить старый backend — не допустимая сверка.

## 6. Откат: что именно восстановлено

| Состояние | Поддержанный шаг | Чего он **не** делает |
|---|---|---|
| До принятого transfer, dispatch отсутствовал | Оставить C и зафиксировать отказ. При ambiguous commit сначала primary/majority readback точной записи/receipt, не повторный initialize/adopt. | Reject/timeout не доказывает, что CAS не committed. |
| A, native dispatch отсутствовал | Под удерживаемым exclusion восстановить исходные **config + unit bytes + active/enabled** внешним restore-механизмом; node readback должен совпасть с `originalSnapshot`. Затем **`handback({node,profile,generation,proofRef})`** с adopted generation. CAS создаёт новую classic generation и handback receipt; adoption evidence остаётся. | `handback` **сам ничего не загружает и не рестартует**, не восстанавливает DB/users/group/agent/network, не снимает locks и не удаляет enrollment/history. У v1 нет встроенного durable restore writer. |
| N, ошибка текущей операции | Existing worker/executor имеют operation-scoped rollback/cleanup; фиксировать конкретный terminal outcome и восстановление users. `src/modules/relay-l2tp/workers/topologyOperationWorker.js:L877-L925`, `src/modules/relay-l2tp/workers/topologyOperationWorker.js:L988-L1000` — `rollbackDurableOperation`, `restoreUsersAfterRollback`. | Rollback к baseline **одной операции** не возвращает всё приложение/ownership к classic и не доказывает исходные pre-migration bytes. При failed/unknown restore держатся fences.
