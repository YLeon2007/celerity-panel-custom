# TEST lifecycle vNext/1 — конструкция и граница доказательства

Статус: локальный operational first slice после design spike; не установка, не canary и не GO. Только TEST; PROD исключён. Основание — разрешённый redesign от 2026-10-25. Старые исходники, интерфейсы, guards, packs/pins не меняются. Ни старый backend, ни native-процесс не объявляются Docker-return. Ниже исправленный B1 контракт и узкая реализация, НЕ полный lifecycle.

## 1. Один выбранный путь и инварианты

Выбран `prebuilt-native / pinned-kernel / finite-owner-v1`: независимый конструктор ДО hold создаёт F (новая версия, временная), R (чистая обычная rollback-версия), D (чистая обычная новая версия для redeploy). Старый backend остаётся исключённым. Источник R — принятый rollback artifact, не thaw старого PID. Порядок serving: F → R → D; каждое переключение проверяет настоящий ответ версии и непустой data-plane E2E. Финальный обычный сервис — D, не «продвинутый» F.

Неизменны: node config/backup bytes и исходные snapshots; owner-generation CAS, история и отсутствие чужих admissions/locks/queue; исключение старых/чужих writers; fail-closed при неопределённости. Lease сети — один исходный абсолютный monotonic deadline, не более 600 s, без выдачи нового lease. Нельзя auto-rollback, удалять COMMIT, править DB напрямую, чистить чужие ресурсы или возобновлять прерванную последовательность.

Изменено явно: return identity — independently built native R/D с собственными unit/cgroup/netns/mount/executable/config pins вместо Docker inspect/DNS/backend identity. Эквивалентность означает serving, rollback, redeploy, storage, node management и update, а не совпадение контейнерного ID или oldConfig. Caddy получает три полных заранее проверенных config, отличающихся только закреплённым upstream; TLS, routes, headers и persistence не теряются. Старые проверки продолжают отвергать новый тип.

## 2. Доверие, реальные capabilities, эффекты по фазам

Trusted: root/PID1, ядро, отдельно проверенный constructor, неизменяемый release artifact, Caddy и код приложения. Root вне этой границы может нарушить любой fence; JSON grant/ACL не заменяют физическое исключение. PID/start из JSON — лишь описание. Авторитет — удержанные живые pidfd, proc-dirfd, namespace FDs, cgroup dirfd и ограниченные resource FDs одного запуска. Открытие и повторные чтения обрамлены проверкой pidfd. Это обнаружение drift, НЕ атомарное исключение concurrent fork/migrate/rebind.

PREPARE, до первого эффекта lifecycle: создать новый durable journal `lifecycle-vnext/1` с boot, generation, deadline, точными artifact/config/endpoint/resource hashes и единственным original-owner invocation. Затем действительно закрыть admissions, дождаться штатных finalizers, запретить legacy relaunch/restart, опустошить допустимые очереди штатным путём. Не «санкционировать» их снимком DB. Старые COMMIT сюда не импортируются. Constructor создаёт новые ресурсы только под этим owner и сохраняет FDs; ни Docker API, ни Docker DNS после входа в HOLD. Docker/containerd/updater сохраняют старый freezer barrier; старый backend никогда не thaw.

HOLD: тот же finite owner проверяет peers Caddy/Mongo/Redis через pinned proc/netns/cgroup/mount/socket identities, health по фиксированным адресам и config readback. Для TCP нужен listener inode из `/proc/<peer>/net/tcp*` + socket FD того же peer и эксклюзивная заранее построенная p2p-топология; SO_PEERCRED из spike НЕ переносится на TCP. Смена PID, listener, cgroup, mount, namespace или restart — отказ, не re-pin. Caddy config endpoint заранее закреплён; нет поиска по имени. Только точные switch F/R/D, принадлежащие этому run network rules и node CAS разрешены. F/R/D не имеют Docker socket, host-control capabilities или writable чужих binds; admission/bootstrap gate предшествует любым app background writers.

Последовательность того же owner (коррекция B1): включить временный F → проверить serving/E2E → закрыть F admission/writer gate, drain и остановить ТОЧНЫЙ F через original pidfd/закрытый cgroup → доказать F `populated=0` и полный task/thread EMPTY → только затем включить временный R и проверить настоящий serving rollback/E2E → закрыть/drain/stop exact R и доказать EMPTY. F/R не пересекаются как writers; обе invocation имеют того же original owner, boot и исходный абсолютный deadline, включая grace. Независимый от owner исполнитель прекращает КАЖДУЮ временную invocation при owner death и expiry; одного network expiry недостаточно для DB/background effects. Живого precommit D нет: D artifact/config/storage/normal network подготовлены, но запуск запрещён до доказанного durable terminal COMMIT. После public all-five handback и COMMIT допускается только новая normal D invocation, никогда in-place promotion F/R. На каждом переходе journal intent fsync и фактический readback; EMPTY охватывает все задачи namespace и требует construction no-fork/migrate/escape. Локальные pidfd tests этого не доказывают.

## 3. Конечный owner, ordinary service и terminal transfer

Original owner — новая one-shot unit `c3-test-lifecycle-vnext.service`, `Restart=no`, `KillMode=control-group`, original boot-bound absolute deadline. ВСЕ временные F/R и их finite supervisors принадлежат одному exclusive owner subtree, без делегации/миграции. PID1 stop-on-owner-loss обязан охватывать весь этот subtree, не только F; `Restart=no` сам по себе не останавливает живой R. Независимый finite supervisor каждой invocation удерживает original owner pidfd и peer pidfds, начинает termination не позднее deadline−grace, завершает exact child к исходному deadline. Смерть supervisor fail-closed для его app; helper не получает продления/вечного holder. Network expiry отдельно прекращает established flows к тому же deadline и не заменяет termination DB/background writers. Physical constructor обязан обеспечить no-escape и проверяемый EMPTY; ни наличие такой unit в контракте, ни локальный PDEATHSIG этого ещё не доказывают.

R — временная rollback invocation того же bounded owner, не отдельная переживающая owner normal unit. Normal D — только отдельная `c3-test-app-vnext@redeploy.service`: заранее constructed, но НЕ запущена до доказанного terminal COMMIT. Никакого temporary D, precommit D E2E или in-place promotion. Для F/R/D требуются fixed unprivileged User, NNP, пустой capability bounding set, private namespaces, read-only release/runtime и exact writable state/config mounts; schema/storage должны быть совместимы с настоящим предыдущим R, иначе PREPARE запрещён. Локальный тест одного artifact под метками F/R не доказывает rollback версии.

Перед terminal owner уже завершил exact F/R stop, EMPTY и temporary network cleanup. Separate normal D path заранее сконструирован, но закрыт и не serving. Доказанный durable `ENABLE_DURABLE` связывает полный accepted public all-five handback, final generations/receipts/originals/history, exact D unit/artifact/config/storage и normal network policy (не ещё несуществующий PID). Только после proven durable binding допускается один bounded PID1 start НОВОГО normal D; его pre-import validation проверяет отдельную normal authority, без lifecycle FDs. PID1 `Restart=on-failure` затем относится только к normal current-generation startup, не replay run. Owner подтверждает serving/readbacks/E2E, закрывает capabilities и естественно выходит. При unknown commit dispatch запрещён; partial JSON/fsync отдельно не authority. Реального adapter для этого binding в первом срезе нет, поэтому D dispatch закрыт без опции «commit=true».

Обычные node operations, backups/restore и generation checks остаются у приложения; новый bootstrap должен сохранить их без привилегированных host binds. Self-update сохраняется явным новым native adapter: существующие version whitelist/re-auth/HMAC/status semantics `src/services/updateService.js` → отдельно версионированный endpoint → конечный deployment job, готовящий новый immutable release и normal service switch. Legacy Docker updater не вызывается и остаётся исключённым. Это обязательная работа будущей реализации, не уже доступная возможность. Native adapter не удерживает прежнюю generation/lease и не размораживает daemon.

Peer persistence — pinned durable volumes, не ephemeral copies. Длительный normal restart/backup/restore Caddy/Mongo/Redis при замороженном Docker требует заранее созданных native PID1 peer units и проверенной offline data transfer ДО hold; затем pin именно их, не adoption старых процессов. После закрытия старых writers выполняется согласованный dump/restore в НОВЫЕ volumes с проверкой последней записи; одновременный writable mount старого volume запрещён. Это часть выбранной конструкции: без неё заявлять ordinary management эквивалентным нельзя. Ни миграция, ни peer restart здесь не выполнены. Во время hold peer restart запрещён; после terminal peer units обслуживаются PID1 как обычные сервисы, не как держатели exclusion. Legacy daemon и его очереди не выпускаются вообще. Цена — отдельное заранее проверяемое service/storage deployment, а не разрешение queued Docker work.

## 4. Ошибки, первый implementation slice и physical acceptance

До COMMIT: drift/deadline/потеря owner → независимое прекращение КАЖДОГО временного F/R и temporary gates/network, без thaw/rollback/lease reissue; уже принятые DB/remote effects не объявляются отменёнными. COMMIT persistence/readback unknown → `COMMIT_UNKNOWN_NO_ACTIVATION`, никакого dispatch/replay; возможный durable commit не стирать. Только ПОСЛЕ доказанного durable COMMIT и потери activation ACK → `COMMITTED_UNKNOWN`: normal D мог законно получить authority; retained exclusion D не обещается, автоматический stop/retry/rollback запрещён. Это уже разрешённая 21 октября семантика, не ослабление precommit/candidate/foreign exclusion. Подтверждение требует read-only exact-generation journal/gates/config/network/PID1 и serving/E2E; JSON boolean, reboot или partial record не дают replay. Natural owner exit — original pidfd + PID1 result; SIGKILL deadline termination не natural app exit.

Первый operational source slice (локальный, не deploy-ready):

- `scripts/test-node-isolation/lifecycle_vnext_supervisor.py`: single-purpose F ИЛИ R invocation, direct child pidfd, independent owner/peer loss и исходный deadline; private exact-token STOP, no repin/restart. SIGKILL supervisor закрывает exact app kernel PDEATHSIG; descendant no-escape этим не доказан. Stopped owner не продлевает срок. Journal — observational fsynced JSONL, НЕ COMMIT authority.
- `scripts/test-node-isolation/lifecycle_vnext_bootstrap.cjs`: versioned pre-import local capsule/boot/role/deadline/index hash admission, потом настоящий `index.js`. Старый `C3_SETTINGS` reader используется без изменения только как file settings; flags=false НЕ writer authority. Нового accepted writer-generation/bootstrap adapter пока нет.
- `scripts/test-node-isolation/lifecycle_vnext_native_contract.json`: конкретные unit names/properties, F/R schedule, budgets, normal-D prohibition, required native storage/network/authority closure. `installable=false`; не созданные/не проверенные systemd/ns/mount facts не выдаются за исполненные.
- `tests/lifecycleVnextSupervisor.test.py`: реальные disposable Node процессы; RED owner SIGKILL для F/R сохранён с исходником baseline. Wrong token/invocation, exact stop/foreign survival, owner stop/deadline/grace, app/peer/supervisor death, late-start и D refusal.
- `tests/lifecycleVnextApplication.test.py`: копия tracked actual app, отдельный настоящий Mongo, настоящий Redis ТОЛЬКО если доступен binary; actual HTTP, sequential same-owner/same-deadline F/R и owner/deadline/app/peer faults. Один artifact под F/R — НЕ предыдущая версия. Если Redis недоступен, degraded Mongo/HTTP проверяется отдельно, readiness обязана остаться 503, и named required-Redis test FAILS, не скрытый skip/PASS.
- `scripts/test-node-isolation/lifecycle_vnext_run.py`: один serial hermes-heavy replay, focused classic regression, версии доступных dependencies против текущего lockfile, полные логи/exit/test-name counts/hashes и gateway before/after. Read-only deps без слепого whole-tree equivalence. Actual Mongo8 standalone/loopback не равен TEST Mongo7 authenticated rs0.

Точечная review-repair SR1/SR2 (только LOCAL fixture): observer больше не открывает PID из STARTED. Supervisor передаёт original direct-child pidfd и один self-opened supervisor pidfd через унаследованный private SOCK_SEQPACKET/SCM_RIGHTS, только при `--local-fixture`; packet связан с invocation/role/boot/original deadline/index hash. Original owner по-прежнему сам открывает свой pidfd один раз на всю F/R-последовательность. Задержанный до reap observer получает DEAD original descriptors либо отказ, а не новую authority по PID/startticks. Невалидный/частичный/truncated/EOF packet закрывает только уже полученные descriptors; отказ не даёт права сигналить ими. Это fixture fault-injection export, не physical observer или расширение native capabilities. Прямое открытие unreaped Popen peer отдельно от исторического journal lookup.

Runner требует новый output root и создаёт отдельный новый каталог для каждой suite с явным `C3_REAL_EVIDENCE`. Повтор root/suite отказывает до dispatch и перезаписи. Command ledger, stdout, source manifest и finalized evidence hashes привязаны к каждой suite; Python completion/success/subtests и TAP counts проверяются отдельно от exit. `tests/lifecycleVnextReviewRepair.test.py` проверяет коллизию через настоящий dispatch с маленькими внешними fixture-процессами; их map/array явно HARNESS, не outcomes приложения. Disposal regression вводит отказ после настоящего tracked readonly-copy, до первого peer: cleanup зарегистрирован заранее, порядок app children → DB clients → peers → дерево, ошибка не пропускает остальные cleanup и не скрывает исходный test failure. Owner traverse/write восстанавливается preorder только внутри собственного disposable дерева, без symlink traversal, privileged удаления или chmod registered source/shared deps. Эти исправления не реализуют full EMPTY/drain, genuine previous R, независимый expiry зависшего supervisor или D.

Остаются обязательными: root-enforced native immutable constructor и private mount/cgroup/ns/network no-escape/expiry/EMPTY; offline native migration со state/auth/index/history/TTL/session/cert readbacks; настоящий previous R artifact, Caddy external serving/node/config/backups/nonempty dataplane; public all-five terminal adapter, fresh normal D без lifecycle FDs, postcommit restart/persistence и native update. Первый executable path намеренно отказывает physical/root invocation и не имеет D activation entry. Это не полная миграция платформы и не synthetic handback из JSON.

Это ещё не разрешение install: отдельный следующий review обязан проверить constructor/unit/storage/bootstrap/update-adapter closure перед privileged physical test. Исходные `fresh_network.py`, `fresh_physical_observe.py`, `heldTestOwnerSettlement.js` не переподключать к vNext и не менять pins. Отсутствующие runtime pieces — engineering gates, не недостающее пользовательское согласие на redesign.

Parent physical acceptance позже: 1) PREPARE clean F/R/D и native peers, запрет legacy restart/queues, storage restore; 2) freeze всего прежнего CONTROL и backend, записать нулевой Docker/API/DNS трафик при hold; 3) настоящий Caddy F→R→D с external serving version, непустыми Xray/PPP E2E, config/backup/generation readbacks; 4) принудительные drift/rebind/restart/fork-escape/mount faults — отказ без adoption; 5) exact F stop, полный EMPTY, natural supervisor/owner exits; 6) owner death и deadline до enable без lease extension; 7) durable enable с потерей ACK — D может служить, только COMMITTED_UNKNOWN; 8) PID1 restart D и peers, persistence, normal node management и self-update через native adapter без legacy thaw. Любая непроверенная capability запрещает acceptance полного lifecycle.

## Локальный executable proof и результат первого среза

Фактический первый replay: process suite 9 named tests PASS, classic-settings 6 PASS. Actual-app suite НЕ исполнила ни одного test body: Mongo отказал при setup, потому что index-build budget 32 MiB меньше допустимых 50. Поэтому настоящий `index.js` serving с Mongo/Redis здесь НЕ доказан, B1 physical acceptance и operational vertical slice остаются INCOMPLETE. Один hermes-heavy завершился 1; gateway MainPID=335804/NRestarts=980 до/после одинаковы. Никакого TEST switch/PROD/deploy или terminal authority не было. Полные RED/final логи и result.json — в `full-production-20261025/lifecycle-vnext-operational-child/` родительского evidence дерева.

Ниже сохраняется прежний отдельный kernel spike proof (не evidence нового actual-app serving):

Реальны: собственные subprocess, pidfd/proc-dirfd, удержанные namespace/exe/cgroup FDs, AF_UNIX listener, SO_PEERCRED, echo bytes, exact pidfd SIGTERM и естественный exit другого child.
