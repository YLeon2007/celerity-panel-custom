# v1.4.0 — памятка оператора

[English](release-v1.4.0.md) · [Список изменений](../CHANGELOG.md)

## Переход с 1.3.3.12

1. Дождитесь опубликованного MAIN выпуска и сверьте коммит `v1.4.0` с объявленным MAIN. Не обновляйтесь с движущейся ветки или `latest`. До окна обслуживания запишите текущий коммит и образ для отката. Сохраните проверенную резервную копию MongoDB, `.env`, Compose-файлов и `mongo-keyfile` с ограниченными правами доступа. Сохраните **прежний `ENCRYPTION_KEY`**: он нужен для чтения существующих секретов.
2. Для существующей установки из исходников проверьте, что рабочая копия чистая, используется тот же Compose-проект, том Mongo и файл окружения. Штатный Compose 1.3.3.12 уже рассчитан на replica set `rs0`; для общего справочника учёток и допусков БД должна поддерживать транзакции и иметь PRIMARY. Если используется standalone Mongo, остановитесь до включения этих функций: переход на replica set — отдельная операция, а не замена тома.
3. Выберите проверенный коммит выпуска. В существующем `.env` задайте нужные флаги (ниже). Для штатного source Compose в окне обслуживания соберите и пересоздайте только панель: `docker compose -f docker-compose.yml up -d --no-deps --build backend`. Не запускайте установщик заново и не удаляйте тома. Для нестандартной установки используйте её собственный механизм развёртывания с тем же закреплённым выпуском.
4. Проверьте `/health`, затем войдите в панель и сравните список нод, карту, подписку и раздел L2TP с состоянием до обновления. Обновление не требует Apply или Install. До любых изменений просмотрите Preview; `/health` и `deployed` не подтверждают работу PPP — для этого проверьте оба ожидаемых выхода с клиента. При расхождении не применяйте изменения. Откат приложения на сохранённый образ с прежним окружением сам по себе не откатывает данные БД.

## Флаги и первые действия

| Переменная backend | Когда нужна |
| --- | --- |
| `C3_REBUILD_ENABLED=true` | Включает Rebuild. При отсутствии переменной или `false` режим выключен. Несовместимые strict/classic-флаги оставьте выключенными; `C3_SETTINGS` и `TOPOLOGY_TEST_STARTUP_MODE` не задавайте. [Список конфликтов](rebuild-mode.md). |
| `C3_REBUILD_L2TP_INSTALL_ENABLED=true` | Нужна вместе с Rebuild для допуска релея и кнопок Install/Remove. Сама ничего не устанавливает. |
| `C3_REBUILD_L2TP_RELAYS_JSON` | **Необязательна.** Если допускаете релеи через панель, список можно не задавать. Это отдельный операторский список; его записи доступны в UI только для чтения, а запись БД не может перекрыть конфликт с ENV. |

## L2TP на релее

- **Установка на чистый релей.** На странице L2TP сверьте отпечаток SSH-ключа и идентификатор машины с доверенной записью, затем подтвердите допуск. На поддерживаемом Debian 13 amd64 с таким допуском Install установит недостающие пакеты strongSwan, xl2tpd, PPP и nftables. При допуске только из ENV пакеты по-прежнему нужны заранее. Install использует отдельные источники и кэш APT; откат L2TP не откатывает пакеты.
- **Если Install прервался,** нажмите «Проверить и продолжить», когда панель предложит это действие. Панель проверит, что произошло, и при необходимости завершит очистку, но не запустит Install повторно. Начинайте новую установку только после сообщения «Можно установить заново». Если результат неизвестен, не снимайте блокировку.
- **После перезагрузки релея или перезапуска службы** панель сама проверяет, что это та же установка, прежде чем показать число сеансов PPP/IPsec или разрешить изменения. Неизвестное число сеансов — не ноль. Install записывает в `modules-load.d` все восемь нужных модулей ядра, даже если они уже загружены. Для Xray 26.11 панель проверяет локальный SOCKS-вход, даже когда Xray открывает UDP-порт только по запросу.

## «Удалить L2TP» или «Удалить релей»?

**«Удалить L2TP»** снимает L2TP только с выбранного релея. Активные сеансы блокируют удаление. Создание, отключение и удаление общей учётки действует на всех релеях с L2TP. При снятии L2TP учётки сохраняются; каждый релей выдаёт адреса из своего пула.

**«Удалить релей»** удаляет ноду, её связи и записи учёток этого релея, но сохраняет общий справочник. Если релей **онлайн**, предпросмотр показывает число активных клиентов; для разрыва соединений нужно явное подтверждение. Обычные обновления статуса и трафика больше не сбрасывают предпросмотр. Если релей недоступен, режим **abandon** удаляет его записи из панели, но не очищает недоступный сервер. При отказе соседа панель указывает его имя и причину вместо общей ошибки 503. Статус `PARTIAL` означает, что удаление не завершено.

## cc-agent 1.5.1

Если `users.json` повреждён, агент сохраняет действующих пользователей Xray и ждёт успешного полного `/sync` от панели. Обновление панели не обновляет агентов. `nodeSetup` использует `releases/latest/download`; одного тега панели для доставки 1.5.1 недостаточно. Ручная сборка агента создаёт артефакт Actions, а не файлы GitHub Release. См. [проверку локального комплекта](development/node-setup-offline-agent.md).

## Ограничения

- После перезагрузки панель не распознаёт L2TP, установленный до v1.4.0, если нет записи о последней применённой конфигурации (`currentApply`). Переустановите L2TP в окно обслуживания; не снимайте блокировки и не обходите проверку.
- Пин пакета systemd для Debian 13.0 (`257.8`) на живом релее не проверен. Живая проверка прошла с `257.13`.
