# Preliminary offline node-side intent journal (dormant)

This is a **local contract experiment only**. It is not installed on a node, invoked by workers, reachable through SSH, or an enforcement point. It cannot prove process-tree quiescence, authorize a remote command, or make the current production transport safe. Production topology/L2TP dispatch remains fail-closed independently of this module. Do not interpret `"blocked"` as permission to run anything.

`journal.py` exposes only `initialize(private_absolute_directory, generation)` and `record_intent(private_absolute_directory, generation, command_id, sha256_hex_digest)`. The caller must create a private owner-only directory per node, on a local filesystem with working SQLite WAL and fsync semantics; do not use network filesystems. Initialization creates a new database only when its path is absent. No epoch rotation or reset exists. One first attempt in the active generation is recorded transactionally with `blocked=1`; after commit and directory fsync the call returns `"blocked"`. An exact duplicate also returns `"blocked"` only when the epoch contains exactly one intent; changed digest, different generation, second command, multiple intents, unsafe file or invalid state reject. There is no command text, execution, clear, dispatch, or proof API. The SQLite file and its WAL/SHM are private. The database is not a tamper-evident ledger: deletion, malicious same-UID modification, storage dishonesty, and independent command routes are outside this contract. Do not use it as evidence that commands are fenced in production.

Path trust boundary: real/effective UID and GID must match. Each directory component must belong to root or this UID; group/other-writable ancestors are allowed only with the sticky bit (e.g. a root-owned `/tmp` protecting a user-owned child). The store itself must be owner-only. The journal uses SQLite's pathname-based URI and pathname-based pre/post checks, **not** an fd-anchored SQLite VFS. This contract assumes root and every process sharing this UID are trusted not to rename or replace these directories/files concurrently or change permissions/ownership while an operation runs. Do not place this store below an ancestor controlled by a different UID, and do not treat these checks as protection against a malicious same-UID/root actor or a concurrently mutable trusted path. Without that trust assumption there is a remaining TOCTOU race; do not activate this experimental journal as a security boundary.

Offline tests: `python3 -m unittest discover -s src/modules/relay-l2tp/node-artifacts/fence -p 'test_*.py' -v`.
