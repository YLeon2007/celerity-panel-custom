# Rebuild portal exits: local Xray checks

Run `verify-portal-exits.sh --xray PATH --cover PATH --mode reverse|mixed` in a disposable local workspace. The runner creates a private network namespace with only `lo`; it does not mount the host resolver, credentials or service sockets. `--xray` runs the portals and subscriber. `--relay-xray PATH` pins gateway/tail/island, and `--bridge-xray PATH` pins the bridge nodes; either pin defaults independently to `--xray` when omitted. API calls use the same binary as the process that owns the loopback API socket.

To exercise the operator version split, set `XRAY_OLD` to the local 26.3.27 binary, `XRAY_NEW` to the local 26.11.9 binary, and `COVER` to the local cover binary, then run:

```sh
for mode in reverse mixed; do
    ./scripts/native-portal-exit/verify-portal-exits.sh \
        --xray "$XRAY_OLD" --relay-xray "$XRAY_NEW" --bridge-xray "$XRAY_NEW" \
        --cover "$COVER" --mode "$mode" --scoped-matrix || exit $?
done
```

Logs and synthetic profiles remain in the unique evidence directory under `TMPDIR`. In `result.json`, `config_test_actors` and `live_actors` identify the role, version and executable for each config or process; `wire_endpoints` records both ends of each tunnel, and `api_calls` identifies the API owner and CLI. Successful HTTP rows include the origin marker and fresh access-log lines with exact route tags.

- `--chain-probe`: the original two-relay transport experiment, with hand-authored policy rules.
- `--scoped-proof`: authenticated TCP round trips in separate miniature Xray processes using the generated scoped listener/dialer. This checks protocol viability, not the readiness of any deployed MAIN.
- `--scoped-matrix`: the unmodified composer selects paths and routing rules for three portals, two chained relays, two bridge exits, and a disconnected relay. Separate origin markers and fresh access-log entries at each hop distinguish the shared and scoped channels. The runner removes and restores one synthetic listener via the real loopback Xray API, checking that the affected portal blocks and the other portal and shared PPP policy still route. For reverse, listener removal alone does not close established workers; the fixture drops their exact local TCP tuple inside its own network namespace before checking the cut.
- `--staged-matrix`: starts from generated stock profiles, with fixture-only RoutingService and two loopback probes. It binds the new listeners first, checks PID ownership, then adds dialers and appends downstream rules for disjoint ingress tags. It proves the original and staged paths before switching the portal selectors. An existing handler may change only `sniffing.routeOnly`, through an explicitly allowed MAIN restart. Relay preparations precede channel staging; any portal MAIN restart comes after selector cutover. The fixture tests both boot files with the node's Xray, checks the exact bytes before and after publication, then verifies new PID ownership, reverse readiness and that other processes were not replaced (`main_restarts` in the evidence). Rollback reverses those steps and restores the original boot bytes; any scoped TCP drain is local to the fixture. The journaled selector first exercises an intentional terminal wire mismatch: it switches to B, observes the mismatch against the test's expected A, undoes the acknowledged switch and confirms A from a fresh origin receipt. A separate Apply confirms B. Each successful terminal record pins an encrypted readback; these add three HTTP origin receipts per staged run beyond the path matrix below. In the lost-reply drill a separate writer fsyncs the encrypted artifacts and intent, then dies by `SIGKILL` after a real router update. A fresh observer verifies the existing pins; the fixture checks live tags, actions and traffic without replay or ACK. `lsrules` does not expose predicates: a negative control alters one ingress match while retaining byte-identical `lsrules`, the same live process and unchanged boot bytes; P1 moves to the shared exit until the predicate is restored. Unlike the sniffing change, the router and channel changes here are in memory: this fixture does not prove their boot persistence, atomic router replacement or product recovery.

- `--serial-matrix`: drives real MAIN restarts through the cutover journal, without routing or handler API writes. Each step seals its exact before/after bytes, syncs intent before handing off the restart, then reads back the new boot and process generation before ACK. It checks listeners before dialers, proves old and new paths before selection, and restarts changed portals last. A deliberately rejected terminal wire criterion exercises the complete inverse in ACK-reverse order; inverse CAS uses the latest ACK on a node even when a later inverse has restored the same bytes under a different PID and inode. Rollback checks the exact original boot bytes and fresh traffic. A separate journaled Apply confirms the desired boot images and paths. `serial_terminals` and `main_restarts` record terminal heads, counts and generation changes. The parent owns all writers in this private fixture; this does not prove the panel transport, a product writer fence, or recovery after a lost serial reply.

The scoped, staged and serial matrices generate their own `assets/geoip.dat` with just `PRIVATE` (`127.0.0.0/8`) and a synthetic `RU` (`198.51.100.43/32`). P1 with relay Geo enabled gets marker A for the RU address through the tail's Geo edge, but marker B for the numeric non-RU address. P2 with relay Geo off gets marker A for both via the tail's ordinary edge, not its Geo edge; the two A paths have different tags. The domain, HTTP sniffing and shared PPP cases still run. A scoped run checks 17 configs and 19 HTTP marker/block cases; a staged run adds fifteen HTTP checks and verifies both boot configs for each restarted MAIN. A serial run has 28 HTTP checks instead of the API cut test.

The matrix checks Xray syntax of the generated TPROXY configuration. For traffic, it substitutes a loopback SOCKS ingress with the exact TPROXY tag and port; the actual generated ACL, local SOCKS handoff and shared Xray routing still run. It does **not** test kernel PPP/IPsec/TPROXY, the panel's Apply/recovery, public geodata, or deployment. Bridge egress is limited to the two local fixture origins. No mode contacts TEST B or PROD.
