# Fixed fresh supervisor preparation barrier (source only)

The ordinary `fresh_classic_launch.py supervisor` CLI and all old sealed-thaw
predicates are unchanged. A **separate**, fixed, no-argument entry
`prepare_fresh_supervisor.py` is intended for a future independently installed
`/usr/local/libexec/c3-test-fresh-prepare.py`. It is not installed by this code.
It requires UID=GID65531 and empty groups, and reads only fixed root-owned
bootstrap policy and digest-pinned coordinator/fresh source. It never accepts
paths, commands, source callbacks, inventory or GO from a request/environment.

## Why the barrier exists

The inventory includes this exact supervisor PID/start and descriptors **inside**
`SupervisorFiles.lock`: anonymous stdio0-2, prebound control socket3 and the
retained `/state` and `/state/launch.lock` descriptors. These identities cannot be
known before the process/lock exists. Merely generating plausible numeric pins
or extending the five-second activation accept window would not solve this.

`PreparationSupervisorFiles.read_json` performs one self-SIGSTOP on the first
fixed-policy read. `supervise` already holds the actual private flock and has
checked both attempt paths absent at this point. No policy is finalized, receipt
emitted, descriptor added, socket listened, COMMIT written or child started by
this pause. No accepted inventory is generated by the supervisor. A repeated read
on the same preparation object refuses, even if its first read later failed.

## Separately required installation/acceptance sequence

This is a sequencing contract, **not a runnable installer or authorization**:

1. Before any all-five maintenance hold, independently prepare the source/runtime
   closure, initial trusted bootstrap policy, private resources, empty anonymous
   stdio, prebound root control socket3 and the dedicated unit/UID/namespaces.
   The bootstrap contains the final immutable `files` map, including the exact
   coordinator and fresh source pins. It is NOT accepted final live inventory.
   Use isolated Python with bytecode disabled and `LC_ALL=C`: a local runtime
   probe without the C locale observed host locale/gconv mappings. Operational
   acceptance must inspect actual mappings, not infer them from ELF NEEDED.
2. Start the fixed preparer in its actual final process/resources. Observe its
   real SIGSTOP, exact PID/start, held-lock-phase descriptors and resource state
   from the separately authorized root provisioner. Do not signal or restart any
   existing backend/candidate/service. No already-held run may be edited.
3. While it remains stopped, finalize only the independently reviewed policy /
   live inventory, make the root and proc readonly with the exact supported
   mounts, and capture/accept final mountinfo/routes/root/namespace/fd/unit and
   source identities. `files` MUST remain byte-for-byte the same mapping: after
   continuation the source refuses `FRESH_PREPARATION_SOURCE_DRIFT` otherwise,
   preventing already-loaded Python code from diverging from the final policy.
   No supervisor-written policy, receipt-as-GO or optional fd pins are allowed.
4. The external operator/installer must enforce a finite preparation deadline.
   A stopped process does not handle its own timers. If preparation is incomplete,
   abandon/dispose it before COMMIT; never begin the irreversible hold and hope
   someone wakes up. Do not resume or automatically adopt an abandoned generation.
5. After independent physical acceptance and complete all-five admission plans,
   the fixed fresh root composition keeps this supervisor stopped throughout the
   public all-five owner settlement. In the **same live Coordinator**, terminal
   `fresh-handback` calls `FreshLaunch.run_prepared` only after the public CAS /
   majority-readback phase. It rechecks all five holds and the accepted stopped
   PID/start, source closure, root/mount/routes/namespaces, descriptors, dedicated
   identity and loaded one-shot unit. A pidfd is opened before these checks; no
   PID-based signal fallback exists. One SIGCONT attempt is latched on that
   Coordinator, including any later readiness failure. Existing sticky restore
   intent prevents a new Coordinator from replaying the attempt.
6. A guarded, at-most-three-second wait (also capped by the Coordinator deadline)
   observes the **same pinned fd3 inode** in `/proc/PID/net/unix`: stream, bound
   pathname, unconnected state, and kernel `SO_ACCEPTCON`/LISTEN flag. The pidfd
   must remain live and PID/start equal before and after observation. Neither
   pathname existence, leaving `T`, nor a consumptive probe connect is readiness.
   Only then does the existing single authenticated connect / prepared / durable
   COMMIT / SCM_RIGHTS / exec protocol proceed. The pidfd remains owned through
   this finite protocol and is closed on every path, preserving the primary error.
   Host policy and executed source pins are checked again before COMMIT.
   SIGCONT is NOT GO: the supervisor's original full policy/filesystem/mapping/
   capability/mount/fd checks still run before listen and again before exec.
   The ordinary **five-second** accept is unchanged, not restarted or extended.

The fixed local scheduler is implemented; physical installation, preparation
lifetime enforcement, unit/resources/ingress and independent acceptance remain
unimplemented/unaccepted. A resume/readiness failure never retries, reconnects,
re-stops, adopts, opens candidate admission or invokes sealed classic thaw.
After possible exec, all result/fsync/cleanup uncertainty remains committed
activation unknown. No held check is made after terminal handoff releases holds.
Merely receiving a stopped PID is not physical GO. This addition does not
provision mounts/namespaces/ingress, widen host admission, or authorize live
TEST/PROD operations. Changed coordinator/launcher bytes invalidate previous
candidate/source-pack pins; a separately reviewed rebuild is required.

## Local tests

`test_fresh_supervisor_preparation.py` uses real disposable subprocesses,
SIGSTOP/SIGCONT/SIGKILL, files and flock: final bytes read only after continuation,
lock retained during stop, no return on abandonment/source drift, no second
preparation, wrong path refused without a signal, ordinary reader unpaused, and
unprivileged/argument entry refusal. Root ownership/path reading is modeled only
inside the test child, explicitly not a physical positive. Full existing launch
regressions are run separately; no actual installed root is claimed by these
unit tests.

`test_prepared_resume.py` additionally exercises pidfd-only continuation, actual
fd3 kernel LISTEN observation without consuming accept, live same-start checks,
flock retention, death/identity/fd mismatch, pidfd absence, each nonselected hold,
remaining-budget expiry and silent checkpoint pipes. The controller's real
predicates run against explicitly modeled proc/cgroup/unit/route/root topology
with real file hashes and O_PATH/fstat/fdinfo. Postexec EOF/fsync/cleanup remain
unknown, with one signal/exec and candidate exclusion unchanged. The owner-bridge
positive test holds the preparer stopped beyond five seconds before its terminal
proof. These tests do not perform physical acceptance, installation, mounts,
namespace changes, live service/SSH/TEST/PROD operations or actual-app acceptance.
