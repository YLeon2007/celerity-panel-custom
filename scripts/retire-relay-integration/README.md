# Relay retirement integration fixture

Run on Linux with Bubblewrap/user namespaces, Node.js 22+, `ip`, and an existing local `mongod` binary and `node_modules` directory. MongoDB and the Express test listeners run only on loopback in a private network namespace. No existing database, panel entrypoint, cron, Redis, SSH connection, Xray or L2TP daemon, installer, or service manager is used.

```sh
export MONGOD=/absolute/path/to/local/mongod
export NODE_PATH=/absolute/path/to/local/node_modules
# REST deletion guards and graph/store cases:
scripts/retire-relay-integration/run.sh graph
# Those same cases plus public preview/confirm and installed Remove:
scripts/retire-relay-integration/run.sh public
```

Both modes use **HEAD** for product sources by default. An optional second argument selects another complete local Git commit that contains the matching product sources; no fetch or uncommitted product overlay is used. The runner stages that source read-only in a disposable directory and takes its fixture JS from the invoking checkout. It prints the source commit and hashes of the fixture JS, Node and `mongod`. Bubblewrap scrubs the environment and isolates the network, PID and mount namespaces. The child verifies a distinct netns, an up loopback as the only interface, and no IPv4/IPv6 routes in the main tables. Mongo is bound to `127.0.0.1`, uses private tmpfs data, and must be the exact single-member writable primary before tests. Save stdout/stderr and the runner's exit status together; passing TAP without a successful original Mongo child wait is not a pass.

| Case | Real seams and assertions |
| --- | --- |
| Bare `DELETE /api/nodes/:id` | Actual REST router, authorization/scope middleware, and writer fence refuse both a lone inactive incident tombstone and an enrolled grant with no links, install state or accounts. No business writes or BSON drift. |
| Abandon graph + store | Actual `retireGraph`, composer, user projection, lock, profile comparison, and `createRetireStore.finish`. Both detached sides and the tombstone neighbor read back MAIN and BRIDGE before a single native transaction. The graph never opens target transport; it still reads local database evidence. A separate client sees the preimage before commit; afterward the intended removals, new survivor applied receipt, account directory backfill and grant suppression are visible and unrelated rows/profiles are unchanged. |
| Transaction abort | Injects an error after the real store finalizer, while the graph transaction is still open. One real abort, no commit, and byte-identical BSON from a separate client. Does not imply remote rollback. |
| Failed second neighbor | With a valid preview, the first survivor passes preflight and the second refuses. No stage, activation preparation, profile put or settlement transaction, and no persisted change. Separate post-put readback corruption also prevents settlement but deliberately leaves the modeled writes in place. |
| `public` abandon | The real `/panel/nodes` renders EJS, then the shipped script runs in a VM with a small DOM adapter. Preview probes target `/info` and SSH admission and receives modeled `ECONNREFUSED` on both. Confirmation goes through the real ingress, ticket/CSRF handling, controller, graph and Mongo finalizer without probing or reading profiles from the target. Success consumes the ticket and requests reload; a separate confirmation fails at the second survivor of the apply preflight, also without target transport. |
| `public` installed online | Real loopback HTTP `retire/confirm` calls the joined L2TP Remove backend and graph. Zero-client delete and explicit force with two modeled clients each verify three ordered native commits (Remove reservation, Remove publication, graph settlement), modeled target cleanup, MAIN/BRIDGE writes and readback on the target and all survivors, preservation of subscriber interfaces, and target DB removal. |
| `public` online refusals | Busy without force gives the client count. A changed census gives `PREVIEW_CHANGED` and a new ticket when the replacement census is admissible, even if its count is unchanged. In the model, equal nonzero PPP/IPsec tallies that lack a trusted join, or tallies above the 32-client force cap, return `activeClients: null`; the reachable target stays `online` but the preview is blocked and has no ticket. These requests do not prepare or dispatch Remove, stage profiles, or write business rows. Force does not bypass CSRF or a changed protected subscriber interface. |

**Model boundaries:** The authenticated HTTP session is a fixture input, not a login test. The shipped browser script runs with modeled DOM, events and reload, not a real browser. Survivor activation and profile IO use stateful in-memory transports; the real graph verifies their readback. In online cases, a mocked agent `/info` succeeds and a simulated SSH peer/channel receives commands from the actual DIRECT driver and target graph transport. The peer checks the installed receipt, CHAP projection, applied listener and census token, and models removal of owned resources. The token models a census generation, not native PPP/L2TP/IKE identity, fencing or per-client teardown. The fixture exercises two-client force and a modeled over-limit refusal; it does not drain a 32-client cohort. The real localhost rate-limit bucket is reset between online cases, not between requests. Database, locks, transactions and HTTP responses are real. Refusal tests allow transient Mongo lock writes and check that the lock is gone on return; post-write readback corruption deliberately leaves modeled profile writes in place. No emitted host command or native relay helper is executed. This is not PPP/IPsec data-plane, full app startup, or live deployment acceptance.
